# 普通观众 auth=2 / auth=3 分支

2026-10-19，静态对照及离线验证。

## 来源

Valve app 730、depot 2347771、manifest 8766757721818354077 的官方 engine2.dll，SHA-256 `6456df18d8f954394024c2c07da8c848df15a5ace74ce7390d78970ceb39ee21`。匿名下载后核对摘要，使用 Ghidra 12.1.4 读取下列函数；原始反编译内容仅保存在本机。

- `0x180057cb0`：读取 challenge 和 auth。两条分支均消耗后续 16 位字段、64 位服务器身份及 8 位标志，再读取上下文。auth=3 检查 Steam key size 必须为零；非 Steam 分支忽略该 16 位字段，遇 secure 标志仅警告。服务器身份为零时，官方使用 GNS 的远端身份补齐。
- `0x180055a10`：connect 接受 auth=2 或 auth=3。auth=2 保存服务器身份而不调用票据 helper；auth=3 调用虚表 `+0x170`。其他 auth 被拒绝。
- `0x18007e9a0`：成功取得票据后才设置消息 `+0x40` 的位 2 并写入 `+0x68` 的 auth 字节。auth=2 分支不执行该路径，connect 的 auth_steam 字段不发送。
- `0x1800578e0`：将接收的 auth 和服务器身份交给 connect 构造函数；原型不实现强制降级选项。

## 实现

由已验证的服务器 challenge 选择 auth=2/3。auth=3 保留原有 SDK 票据回调与取消路径；auth=2 不请求或构造票据，仍要求正常登录 App 730、认证且加密的 GNS 连接，以及非零远端身份。challenge 带非零身份时必须匹配 GNS；仅 auth=2 的零身份可由当前 GNS 身份提供信任依据。ClientInfo 的账号来自本机合法 Steam SDK 身份。

原生 ABI 升为 2，新增本机身份读取和服务器 auth=2 就绪接口。无票据就绪使用独立状态，不开放 auth_steam 内存，也不受尚未完成票据握手的 30 秒期限误关闭。旧 ABI 在加载时明确拒绝，需要重建便携包。

## 验证

- 30 项 Python 验证通过：auth=2 wire 字段、无票据、账号来源、空/匹配远端身份及错误身份拒绝；auth=3 原有回调门禁仍通过。
- C++ 10 项生命周期验证通过：无票据模式不暴露票据、不请求票据，错误阶段及失效登录上下文被拒绝，关闭只释放已有资源。
- ctypes/C ABI 合成动态库验证通过；使用固定 Valve SDK 1.65 头文件编译实际 sdk_host.cpp 成功。

这些是静态及离线验证。本轮没有连接服务器，也没有生成新的 Windows 测试包。之前完美中继日志出现 auth=2，是调查线索，不能代替普通观众实际连接结果。
