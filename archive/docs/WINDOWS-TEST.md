# Windows 普通观众客户端测试

## 便携客户端主流程

使用本仓库构建的 Windows x64 测试包，解压后运行 `Start.cmd`。保持 Steam 已登录，依次填写 CS2 安装目录、当前游戏 host version、获授权的测试观战地址与普通观战密码。启动器读取 `steam.inf` 提供版本建议值；以当前官方客户端输出为准。密码在本机交互输入。

客户端最多观察 300 秒，结果写入包旁 `runs/<UTC时间>/`。检查报告中的连接、sign-on、解析进度及真实事件；只完成握手或看到程序启动不算接收成功。测试包构建通过与 Windows 实机在线验证分别记录。

下面保留官方客户端录制/日志的对照采集步骤，仅在需要比对时使用；便携客户端主流程直接接收网络数据，不要求先生成 Demo。

## 官方客户端对照采集

此步骤只由用户在本机、使用新提供且仍有效的普通观战授权执行。不要沿用旧源，不连接生产比赛，不重复 dedicated/relay 密码测试。云研究者没有操作用户电脑。所需最少输入是一个隔离测试时段、当前官方客户端、用户自己的 Steam 登录和普通观战地址/密码；登录、密码、票据始终留在本机。

## 1. 普通客户端基准（约 2 分钟）

1. 正常启动官方 Steam/CS2，以正常操作接入本次授权的测试观战源。保持原有 secure 设置。不要使用 `-insecure`、注入器、调试附加、隐藏命令或修改二进制。
2. 连接成功后运行 `version`、`status`，保留可复制的输出及本机 UTC 时间。若命令不可用，保留准确拒绝信息，不将画面可见推导成完整 sign-on 日志。记录当前地图、热身/正式阶段、60 秒内是否确有玩家状态与时间推进。
3. 若需完整连接日志，先在本机查 `help con_logfile` / `help condump`，确认当前版本支持，再进行另一次授权连接。完整日志可能包含地址、密码或身份信息，只存私有目录；分享前仅提取版本、状态编号、时间和断开码，隐去其他原文。不要将密码写进本仓库脚本或启动命令，不上传完整日志。

## 2. 先确认数据出口

控制台先查看 `help record` / `help stop`，然后尝试正常命令：

```text
record mizar_viewer_probe
```

若被拒绝（例如 cheat/资格限制），记录准确原因并停止录制分支。不要设 sv_cheats，不改命令标志，不使用 `_record` 绕过。若接受，找到本次新建的 `.dem`，保持观战至少 60 秒；不要将“命令无报错”作为写入成功。

在另一个 PowerShell 中观察真实大小（将路径改成刚生成的文件）：

```powershell
$demoPath = 'C:\private\mizar_viewer_probe.dem'
1..13 | ForEach-Object {
  [pscustomobject]@{ utc = (Get-Date).ToUniversalTime().ToString('o'); bytes = (Get-Item -LiteralPath $demoPath).Length }
  Start-Sleep -Seconds 5
}
```

仓库根目录先按 README 安装/构建，然后在录制尚未结束时启动解码：

```powershell
pnpm exec tsx client/decode.ts --input $demoPath --output 'C:\private\viewer-run-01' --follow --seconds 90 --offset 120
```

用 `Get-Content 'C:\private\viewer-run-01\events.jsonl' -Wait` 确认**录制仍进行时**就有持续增加的序号和源 tick。最后在游戏控制台执行 `stop`，保留完成文件 SHA-256，另用新输出目录离线重读。对比事件 tick/数量；晚到和尾部完整性差异必须解释，不把不同采集区间机械判作丢包。

需要实际发生的正式 round_start/end、weapon_fire/player_death 才能证明对应事件；热身或纯 cursor 不能代替正式回合。狙击枪和 taser 都需要本测试自然发生或在获授权测试局安排发生，未知武器字符串先保留，不生成假事件。当前公开离线样本没有 taser 覆盖。

## 3. 只有数据出口成立后才测低开销

保留正常设置作为基准，再分别测试低画质、小窗口、适度 `fps_max`（例如 30）和最小化。记录每组至少 60 秒 CPU/GPU/内存、Demo 每 5 秒字节增量、事件输出间隔；若最小化或限帧造成停收/明显延迟，恢复基准。不要称此路径为“无画面客户端”；没有验证过的 `-nullrhi` 参数不进入本次验收。

两种消费时间暂只记录同一接收实例下的源 tick、接收时间，以及用户观察到的对应画面事件时间。120 秒不是测得的提前量；不要执行时间平移后便宣称同步准确。无需先开第二个接收器。

## 4. 出口被拒绝时的最少协议证据

普通观众已可看但无法录制时，优先回传第 1/2 步的脱敏结论。进一步抓包只在用户允许且本机工具可用时执行，短时过滤本次授权端点；无需安装付费反编译器或附加游戏进程。

1. 使用本机 Wireshark 的 UDP+确切主机/端口捕获过滤器，覆盖授权连接前几秒至连接后 60 秒，停止后存私有目录。若观察到 SDR 或实际目标不匹配，记录这一事实，不盲目扩大到全部账号流量。原始 PCAP 不上传。
2. pcapng 本机转换为经典 PCAP，再运行 README 中 `wire.py pcap`。PowerShell 可用 `$env:GOTV_ENDPOINT` 传入用户本地地址；密码不作为参数。输出只包含包形状元数据。
3. 回传版本、时间范围、协议探针摘要、是否出现证书/crypt 字段、断开码及普通客户端状态。高位数据候选包数量增长仅证明候选传输活动，不证明游戏解密、sign-on FULL 或正式事件。IPv6/SDR/分片不支持时回传“不支持”，不要称没有数据。
4. 仍缺的证据：实际普通连接的 auth_protocol、目标身份类型与安全状态、connect 内层 framing/密码字段长度、合法票据回调结果、连续 sign-on/初始化消息顺序。**被加密的 PCAP 无法提供这些内层内容。** 只有客户端已公开的合法诊断出口才能补充；不得要求用户导出票据、密钥、密码或注入进程。若官方出口没有这些数据，后续在获授权的本地测试服务端/可公开诊断接口继续核对，或由平台提供正常客户端集成文档。

## 最少回传清单

- 新测试的客户端版本、UTC 起止时间、测试阶段；不含服务器地址、密码或用户票据。
- 普通观众可见/不可见、状态编号原始行（如有）、连接/断开原因；不是专用服日志。
- `record` 接受或拒绝原文的脱敏片段；若接受，13 次文件大小、最终 SHA-256、decode `report.json`，以及少量隐去 Steam64 的事件行。原始录像默认留本机。
- 若录制出口不可用：可选 `wire.py` 摘要及格式不支持错误。不要上传原始 PCAP、二进制、完整日志或任何认证材料。

足以推进的结果可能是“官方普通观众能看，但 record 被权限拒绝，只有加密外层元数据”。这会明确剩余接口缺口，不包装成已完成接入。

## 一次性采集包（方便时执行，无需现在开机）

新增的 `capture.py` 只读取用户指定的安装目录、可选现有日志/录像，不启动游戏，不连接服务器，不抓包，不读取登录资料。先按上文在一个新授权测试时段正常观战；可录制时再带上 `--demo`。需要 Python 3.11+。

```powershell
python client/capture.py --game-dir 'C:\Program Files (x86)\Steam\steamapps\common\Counter-Strike Global Offensive' --output 'C:\private\viewer-capture-01' --demo 'C:\private\mizar_viewer_probe.dem' --seconds 90
```

录制被拒绝就省略 `--demo`；有既存本机 console 日志可加 `--console-log 'C:\private\console.log'`，脚本只投影有限的状态/协议/错误字段，不复制原始行或票据/端点。当前只识别列出的英文日志形式，未匹配不代表事件不存在。日志解析不是通用脱敏器，原始日志始终留本机。

本机实际安装和录像路径以用户电脑为准，不要照抄示例不存在的路径。安装根目录应包含 `game\bin\win64\engine2.dll` 和 `game\csgo\steam.inf`。输出目录必须不存在。

在另一个终端按第 2 节运行 decode 的跟随命令。采集结束后分享 `capture.json`、decode `report.json` 和录制接受/拒绝结论即可；完整日志、录像、PCAP、票据和二进制不上传。

| 一次采集解答的未知       | 成功/有效证据                                                | 仍不能解答                                           |
| ------------------------ | ------------------------------------------------------------ | ---------------------------------------------------- |
| 云端函数地址是否适用本机 | engine2/networksystem hash 与本文一致；不同则重新定位        | 相同 marketing version 不够；PE 时间戳不证明文件可信 |
| 当前正常观众实际连接阶段 | 原始日志可识别的状态迁移/断开码；用户看到持续推进            | 没有内层消息时不能补写 auth/full 证明                |
| 官方录制出口是否持续可用 | 至少 60 秒文件增长，录制未结束已有新 tick/事件，结束后可重读 | 自有客户端票据/GNS/网络通道及无画面资格              |
| 正式事件是否有覆盖       | 真实 round_start/end、开火/击杀；狙击枪/taser 分别记录       | 未发生的事件不能用合成数据补足                       |

`capture.py` 已在云端对本次官方文件实际运行；Windows 执行和真实观战仍为 NOT_RUN。它是参考样本采集工具，不是轻量观众客户端。
