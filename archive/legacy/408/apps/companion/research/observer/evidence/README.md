# 本轮验证证据

- `demo.json`：329,136,562 字节公开真实 Demo 的完整解析、DAK 依赖解析器独立对照、增长文件实际读取和真实事件的合成双时间轴。首条击杀在生产者只写入 16,908,159 字节、尚未结束时出现；224 条最终事件完全一致。221 条有完整双方身份，余下三条不提供提示资格。
- `cli.json`：四个实际 Node/tsx 子进程；换文件进入第二 generation 并解析完整 224 条、catchup 与追加数据区分、读取中及完成后停止、坏 Demo 非零退出、过期/坏采集的私有提示撤下。
- `validation.json`：本轮环境、命令、当前输入/源码摘要和验证范围。提交 SHA 由所在 Git commit/PR 绑定；源码文件摘要避免生成报告后提交产生自引用。

模拟双时间轴设置 12 秒领先；输出 12 秒说明实现遵守该受控输入，**不测量真实观战延迟**。RSS 为单次 Linux 样例的进程观测，含验证器保存的样例数组，不是接收器的 Windows 长时资源预算。Demo 的首条事件在 EOF 前出现只证明接收消费端可增量工作，不证明 CS2 relay 会及时刷盘。

开发中真实发现并处理的失败：

1. cs2parser 在终态再次 cancel 抛出已解析错误；适配器仅在解析进行中调用 cancel，实际停止场景已复验。
2. 非 Demo 字节可能被上游视作 incomplete；研究入口逐字节验证 PBDEMS2 标识，原始错误与原因链留在私有输出。
3. 只构建 telemetry/core 后，既有投影回归因旧依赖产物缺少 bombDamage 失败；按 Companion 清单重建依赖图后，原断言无修改通过。
4. 一次 CLI 完整解析观察达到实验脚本 15 秒期限；观察器原来每轮重读整个不断增长的 JSONL。改为每轮增量读取最多 64KiB 和有界行尾，仍保留同一 15 秒期限、所有原断言，无 skip/retry。最终新一轮完整 CLI 实验通过。此前失败保留于本说明，不将其改记成功，也不将观察器开销当作唯一已证根因。

本轮没有 CS2 二进制启动、relay 身份接入、真实比赛持续出口、正式画面对齐、真实领先量/漂移或 Windows/OBS 实机证据；全部为 INCONCLUSIVE。原生候选路线及替代路径见上级 README。
