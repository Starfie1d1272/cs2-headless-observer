# 复用指南

## 先选择数据域，再选择组件

1. Schema / 类型系统：从 TYPE 条目开始。名称、版本、类别、维数与 encoder 分开保存，不能按 C++ 大小直接消费 wire 位流。
2. Demo 解析：复用字段路径、标量、容器与表结构结论时，先核对录像的构建和协议分支。普通实时观察者规则与历史 Demo 兼容规则分开；不能为让旧样本通过而改写新构建的 native 规则。
3. DAK 统计：从 ENTITY、IDENTITY、EVENT 和 TABLE 条目组合。槽位、userid、网络实体 handle 与 Steam64 是不同域；只在对应版本与身份一致时关联，不能靠掩码相近或姓名猜测归属。
4. Mizar 运镜：网络 origin、cell/fraction、姿态 wire 值与最终渲染变换分开。COORD、ANGLE、ORIGIN 描述的输入不自动等于父变换、插值和动画后的画面坐标。
5. 本地诊断：记录版本摘要、来源角色、channel/world generation、消息顺序、有效 snapshot tick 与网络时钟。不同时间轴不能相互替代。
6. 传输与初始化：NET、AUTH、SIGNON、WORLD 的证据针对各自层次。SDK 认证与可靠传输复用官方接口，应用层帧、表、实体提交和订阅保持独立。

## 固定证据与实现选择分开

原生行为说明游戏如何处理该路径；本地的队列上限、严格身份拒绝、错误隔离及有界重连属于实现策略，不借原生名义扩大结论。校验脚本成功仅证明结构和引用完整，测试数不代表真实接入成功。

## 更新方式

每条结论保持稳定 ID，修正时同时更新版本范围、直接证据和复现方法。新版本不能直接覆盖旧版本地址或摘要；新增已核实的版本条目。正式参考中不放猜测、待办或未核实项。
