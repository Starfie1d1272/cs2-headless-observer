真实验证覆盖持续收流、开局/冻结期等源实际发出的生命周期事件、控制器身份、比赛结束和正常清理。旧样本的应用通道可以确定性重放。详细历史见[实测记录](../archive/docs/LIVE-2026-10-24.md)。本仓库不附带真实比赛原始材料。

控制器 Steam 身份由当前世界 controller 与 userinfo 一致性证明；pawn 需另外通过完整 serial 等验证。userinfo 空值清除旧身份；缺失不等于选手真实退服。不能复用旧身份填空。

两路事件接收差约 120 秒是特定源的观测，热身过渡存在变化，不是固定偏移保证或 OBS 逐帧校准。部分源不发送另一源具有的事件，不合成 round_start 等补齐覆盖。

晚加入时首个 FULL 水位不合格会请求新完整快照，仍要求合法控制水位后才恢复。该恢复路径已有合成回归，当前修改尚无新的在线 GOTV 验证。正常结束排空已有真实官方 SDK 本地 socket pair 和合成驱动验证；它们不代替远程来源结束验收。未知版本、任意源、同连接换图、任意长时间稳定运行均未自动获得验收。

进程重试由消费者拥有；本程序单次运行拥有一个来源，不自动重连。消费应用的界面和提示产品独立于本体。

上游普通观众能力标记 ordinaryViewerProtocol=2 与有序 IPC 3 是不同字段，不做全局数字替换。

最低外部运行时：Node.js 24.0.0，具备WebAssembly、ReadableStream和structuredClone；小版本不作允许列表。Windows包需要Windows x64 Node；离线源码工具可在对应平台验证。

## 多路连接与游戏客户端共存

本程序使用真实 Steam App730 上下文，Steam 可能显示 CS2 正在运行，虽然没有游戏画面。需要与图形游戏客户端共用账号时，先启动游戏，再启动观察器；重新启动游戏前先停止观察器并等待其进程退出，避免 Steam 阻止再次启动。停止观察器只释放它拥有的会话，不结束已有游戏或 Steam；消费应用负责启动顺序与异常退出回收。

2026-10-24 在 Windows x64、CS2 build 10955 / host 14192、组件 1.0.0-rc.1 和外部 Node 24.21.0 下，三场授权比赛的早源、延迟源共六路均收到真实事件。整体负载采样约805秒，其中六路进程同时存活的采样区间累计约275秒；不构成六路连续长时间稳定保证。

同一 Steam 账号连接不同 IP 或不同端口可以并行；这不意味着同一端点允许重复连接。两场分别复现：第二个客户端连接同一 GOTV IP、端口后，第一个连接收到 1000 / shutdown。游戏客户端与额外观众共用账号及端点时也出现断开关联。因此当前不应依赖它们在同一端点稳定共存。没有不同账号的对照实验，不将此结论外推为所有服务器、账号组合的绝对限制。

1000 本身是通用关闭码，不等于专用“账号冲突”错误码；应结合操作时间、连接端点及实际回执判断。不要用反复自动重连争抢同一连接。早源观众与延迟游戏使用不同端点，不属于这一重复连接情形。

六路采样期间，观众及解析进程合计CPU中位约20.0%、P95约23.4%（全机16逻辑处理器口径），工作集内存中位约2084MiB、峰值约2193MiB。该测量没有直播或录像编码负载，不代表其他硬件或完整制播场景的性能保证。事件接收时间差存在数秒抖动，不能据此承诺固定120秒延迟。
