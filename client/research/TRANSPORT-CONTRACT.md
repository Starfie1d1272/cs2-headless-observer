## Challenge identity fallback is shared by auth2 and auth3
A final comparison against the frozen driver found an over-restrictive branch: driver.py rejects a zero challenge server ID specifically for auth3. Fixed engine057cb0 executes its GNS identity query and zero-ID fill after both the auth3 and non-Steam payload parsing branches. Consequently a genuine authenticated/encrypted GNS peer with a nonzero Steam identity can supply the missing ID for either accepted challenge protocol. Auth3 still requires the real SDK ticket bound to that same peer; this is not a transition to auth2 or omission of ticket validation. A nonzero conflicting challenge ID is only diagnosed by the inspected game function; this observer deliberately retains its stricter mismatch rejection as a local trust policy. During unified implementation remove only the unsupported auth3-zero rejection, preserve actual GNS trust and ticket gates, and test both protocols' zero/matching/conflicting identities. Historical AUTH-PROTOCOL-EVIDENCE.md's auth2-only fallback description is superseded by this fixed-build branch placement.
